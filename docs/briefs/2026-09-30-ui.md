主旨：cow-ui 接手 cow-farm 的畫風探索與完整設計稿，讓使用者直接跟設計 session 討論畫面

## 目標

- 找到使用者喜歡的整體畫風與牛的造型：從第 3 輪接手，畫到使用者明確選定為止。
- 定案後畫 M2 完整設計稿，一次交使用者核准。核准的設計稿就是 cow-app 的實作規格。

## 依據

**使用者裁示（原話，2026-09-30）**
- 第 1 輪看完 R1 三種畫風：「選a 但我不喜歡牛的樣子 要給我另外的設計」
- 重看 R1 的牛：「牛眼睛很奇怪，而且每一隻都長一樣體型，我不喜歡。請在給我三個新版本參考」
- 第 2 輪看完三種牛造型：「側面的好多了，但我不喜歡目前的風格，還有小牛的比例超級怪。請你提供五種新的不同風格的畫風」
- 使用者提議開 ui session 分擔設計：「ui設計我要不要開個ui session來幫你負擔？」

**已經否決的方向**（不要再提）
- R1-A 圓潤Q版（粗圓可可色描邊、扁平粉彩）。
- R1-B 像素風。
- R1-C 軟萌立體。
- R2-A 大頭寶寶、R2-B 繪本自然的牛。

**目前的方向**
- 牛：R2-C 側面輪廓，頭也畫側面、口鼻往前伸，品種之間體型不同。
- 小牛：R2 的大頭、細長腿比例被否決，第 3 輪改成約成牛 55–60% 高、身體短圓、腿有肉。

**文件**（main 上都有）
- `design/spec.md`：各輪裁示的摘要。以設計稿為準，文字只是摘要。
- `design/artboards/round1/`、`round2/`：圖、`src/`（參數化畫牛產生器與畫面）、`harness/`（Playwright 出圖、拼圖）、README。
- `design/artboards/round3/`：五種新畫風（A 水彩繪本、B 剪紙拼貼、C 扁平幾何、D 復古農場海報、E 日系手帳線稿）。由 ceo 的子代理製作，完成後 ceo 會 commit 到 main 並通知你。
- `docs/design/gdd.md`：
  - 第 4 節是各系統規則。
  - 第 8 節是畫面清單 S01–S16 和動畫清單，也就是完整設計稿的範圍。
- `docs/decisions.md`：使用者裁示 D1–D7、設計底線、技術決定。
- `AGENTS.md`：專案規則。

**產品限制**
- 只做 iOS、Android 直式手機 app，不做網站，所以不畫桌機版。
- app 用 Flutter，牧場畫面用 Flame。
- 牛一律由參數化產生器依基因畫出：毛色、花紋、角、體型、毛質、特殊基因。要能量產幾十種品種，也要看得出遺傳。正式版可以在建置時把產生器輸出成 PNG 精靈圖。
- 原創：不能出現「養豬場」「MIX」，也不能沿用其他遊戲的畫風或畫面配置，不用真實品牌。
- 牛肉用「出貨」和禮盒呈現，不畫屠宰。
- 行情顏色照台灣慣例：漲紅跌綠。

## 流程與驗收條件

- [ ] **第 3 輪**
  - ceo 通知 round3 已進 main 後，把 main 合進你的分支，自己用 Read 看過每張圖。
  - 照 `design-review-rounds` skill 呈現：先在對話列出「檔名 → 項目與選項」清單，再用 `eog --new-instance` 開總覽和每個選項，記下 PID，看完再關掉。
  - 收使用者的裁示。
- [ ] 每一輪都照 skill：
  - 檔名 `R<輪>-<項目>-<項目名>-<選項字母>-<選項名>-mobile.png`，圖內左上角印同一個標籤。
  - 另有總覽 `R<輪>-99-總覽對照.png`。
  - README 照 `harness.md` 的欄位寫。
  - 選項用「使用者會看到什麼」描述。
- [ ] 每條裁示連同日期和原話寫進 `design/spec.md` 的該輪章節。
- [ ] 使用者明確選定整體畫風與牛的造型，包括小牛。
- [ ] **M2 完整設計稿**：畫風定案後開始。
  - 範圍：企劃書第 8 節的 S01–S16，每個畫面都要有每種明顯不同的狀態。狀態包括正常、空白、最長或最大數字、連線中或斷線、錯誤、第一次使用。
  - 手機尺寸：430×932、390×844，另量測 360 和 320 的寬度。
  - 動畫（收奶、成交、出貨卡車、小牛出生、升級、發現新品種）要出分鏡和 GIF。
  - 每張圖有固定的頁面 ID，一次交使用者核准；核准前不交給實作。

## 限制

- **記憶體安全**：2026-09-30 這台電腦因記憶體耗盡當機過。
  - 開 Playwright 或 headless Chrome 前先看 `free -m`，available 少於 2000 MB 就等。
  - 指令一律用 `systemd-run --user --scope -q -p MemoryMax=1500M -p MemorySwapMax=0 <指令>` 包起來。
  - 一次只開一個瀏覽器。
- **瀏覽器與字型**：
  - Playwright 沿用 `~/.cache/ms-playwright` 已有的瀏覽器：`@playwright/test` 1.62.0 對 chromium 1234，裝的時候設 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`。
  - 字型只用本機已有的：Noto Sans CJK TC、AR PL UKai TW、AR PL UMing TW。要用其他字型先問 ceo。
- **git**：
  - 在自己的 worktree `~/Desktop/cow-farm-worktrees/ui`（分支 `ui/work`）工作，不動 `~/Desktop/cow-farm` 的共用 checkout。
  - 完成一輪就 push 分支並開 PR 到 main，由 ceo 審後合併；不要直接推 main。
- **用詞**：對使用者用白話中文。「設計稿」是一個畫面一張圖；術語第一次出現附一句解釋。
- **記憶**：用 memoryctl，範圍 `project:cow-farm`。使用者的畫風裁示記成 decision。
- 不提交金鑰；不要開 plan mode 等使用者核准，計畫交給 ceo。

## 回報方式

1. 開工先用 SendMessage 回報計畫給 ceo（session 名稱 `cow-ceo`），ceo 核准後開始。
2. 每輪結束：回報 PR 連結、使用者的裁示原話，以及下一步。
3. 需要使用者決定、但不屬於畫面的事，回報 ceo。
