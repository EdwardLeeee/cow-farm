## 目標

- 正式 app 的每個畫面、狀態、動畫都照 `design/m2/` 第 2 版（D27）做，跟設計稿一致。

## 工作順序（每一項開一個 PR）

1. **排版**：用 `dart format` 排好 `app/`，在 `.github/workflows/ci.yml` 的 app job 加一行 `dart format --output=none --set-exit-if-changed lib test`。
2. **技術查證**：照 tech-decision 做，結果寫進 `docs/research/`。
   - 牛怎麼畫：24 種 × 公母 × 小牛／成牛／老牛 × 側面／正面，加上轉身。比較兩種做法：
     - (a) cow-ui 用產生器匯出 SVG 或 PNG 精靈圖，app 載入。
     - (b) 把產生器移植成 Dart。
   - 同品種的個體微調怎麼保留。
   - 量牧場同時 40 頭牛走動時的 fps 和記憶體。先在模擬器或桌面版量，iPhone 實機等 M4 的 TestFlight。
   - 結論裡列出要 cow-ui 匯出的東西，由 ceo 轉達。
3. **基礎**：
   - 主題照 `base.css` 的設計參數。
   - 三種語言：key 用 `design/m2/i18n/` 的 key。
   - 狀態管理、錯誤碼對應文案、斷線處理。
4. **畫面**：照 S01–S20 和 G 共用元件做，每個 PR 一組畫面。
   - 每個頁面 ID 都要有 widget test。
   - PR 附 430、390 寬的截圖，跟設計稿並排比對。
5. **牧場場景（Flame）**：
   - 場景兩個螢幕寬，可以左右拖動，下面有小滑塊顯示位置。
   - 牛會走動、會轉身。
   - 面板可以收起來，並記住玩家上次的選擇。
   - 細節見 m3-backlog 的 D27 一段。
6. **動畫 A-01–A-12**：每個都要有減少動態版本，跟著手機的系統設定。
7. **帳號（D22）**：
   - 接 `sign_in_with_apple` 和 `google_sign_in`。iPhone 兩顆按鈕一樣大，用官方規定的樣式；Android 只有 Google。
   - Google 登入只要求最少的資料，不拿 email。開工前查 Google 官方文件確認做法。
   - token 的存法照 `backend-findings.md` 的建議：iOS 用 `first_unlock_this_device`；Android 把 `flutter_secure_storage` 用的檔案排除在自動備份之外。

## 限制

- 正式畫面只能照核准的設計稿。設計稿沒畫到的狀態、看得到的改動，先回報 ceo，由 cow-ui 出稿給使用者核准後才做。
- Flutter 用 `~/development/flutter/bin/flutter --suppress-analytics`；這台電腦建網頁版要加 `--no-wasm-dry-run`。
- 記憶體安全照 AGENTS.md：先看 `free -m`，重的指令（建置、模擬器、headless 瀏覽器）用 `systemd-run` 限制記憶體，一次只跑一個。
- 試玩伺服器在 8787 跑（ceo 的 checkout）：不要停它。需要連真的伺服器時，跟 cow-back 要它測試用的埠。
- 金鑰照 secrets-custody：不 commit 任何簽章檔、client secret 或 token。
- 本機只跑和改動相關的單一測試檔，完整測試看 CI（AGENTS.md 的 CI 一節）。
- 在自己的 worktree `~/Desktop/cow-farm-worktrees/app` 工作。每個 PR 都從最新的 `origin/main` 開新分支，不直接推 main。

## 回報方式

1. 開工先用 SendMessage 回計畫給 ceo（session 名稱 `cow-ceo`），不用 plan mode。ceo 核准後再開始。
2. 每個 PR：回報連結、CI 結果和截圖比對結果。
3. 協定有不清楚或缺的，直接問 cow-back（session 名稱 `cow-back`），並副本給 ceo。
4. 需要使用者決定的事，回報 ceo，由 ceo 問使用者。
