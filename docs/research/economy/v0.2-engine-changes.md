## 0. 先講結論

1. **伺服器不改也能 import、能啟動**。所有 v0.1 的名字都保留了，只是有些行為變了，見第 2 節「行為改變」。
2. **一定要改的五件事**：
   - 出貨函式要傳 `rng`，才會抽出貨評級（2.3）。
   - 商店改用 `buy_shop(grade)`（2.4）。
   - 配種改成每頭牛一輩子一次，不再有冷卻；自己的公母配種免費（2.5）。
   - 行情從兩種商品變成三種（牛奶、牛肉、稻米），伺服器寫死 `("milk", "beef")` 的地方要改（1.1）。
   - 新增借種市場 `StudMarket`，這是第一個跨玩家的狀態（2.7）。
3. **舊存檔**：`Farm.from_dict` 讀得進 v0.1 存檔（新欄位給預設值），但規則已經變了：兼用牛變成耕牛、不再產奶。`Exchange.from_dict` 讀 v0.1 存檔只會有兩個市場，之後 `markets["rice"]` 會 KeyError。**原型建議整個重置**，不做遷移。
4. **會壞的伺服器測試**：見第 4 節（實測）。

## 1. 參數（`cowecon/params.py`）

### 1.1 商品：兩種 → 三種

| 項目 | v0.1 | v0.2 |
|---|---|---|
| 商品清單 | 寫死 milk、beef | `COMMODITY_IDS = ("milk", "beef", "rice")`，也在 `EconomyParams.commodity_ids` |
| `EconomyParams.rice` | 沒有 | 新的 `CommodityParams`：稻米，5 幣／公斤，其他機制和牛奶、牛肉相同 |
| `EconomyParams.commodity(cid)` | 不是 milk 就回傳 beef | 照清單取；未知商品丟 `KeyError` |
| `with_overrides({"market.xxx": v})` | 改 milk、beef | 改三種 |

伺服器要改的地方（grep 結果）：
- `server/game.py:22` 的 `COMMODITIES = ("milk", "beef")`。

- `server/runtime.py:473`、`:504` 的 `for cid in ("milk", "beef")`。
- 資料庫 `markets`、`price_history`、`trades` 的 commodity 欄位是 text，不用改 schema，但要讓稻米寫進去。

## 2. 函式與類別

### 2.1 牛（`Cow`）

- 新欄位：`bred`（這輩子配過種沒）、`field`（在第幾塊田，−1 = 沒有）、`listed`（上架借種的編號，None = 沒有）、`origin`（來源，分析用：start、A／B／C、breed、stud）。`to_dict()` 多這 4 個鍵；`from_dict()` 缺的時候給預設值。
- 新方法：`is_busy()`（在田裡或上架中）、`can_breed_now(now)`。
- **行為改變**：`ready_at` 不再因為配種而改變，固定等於 `adult_at`。配種限制改看 `bred`。

### 2.2 產奶、耕田（函式）

- **行為改變**：`cow_milk_rate`、`cow_milk_between` 只有母乳牛（`is_milker(cow)`）才大於 0。耕牛母牛、肉牛母牛都不產奶。
- 新增：`is_milker`、`work_frac`（= `milk_frac`，耕牛工作力用同一條年齡曲線）、`cow_rice_rate`、`cow_rice_between`、`field_cap_for`、`rice_factor`、`field_cost`。
- 新類別：`Field`（`ox`、`rice`、`t`）、`RiceLot`（`qty`、`t`），都有 `to_dict／from_dict`。

### 2.3 出貨與評級

- 新增函式：`beef_condition(fp, cow, now)`、`beef_grade_probs(fp, cow, now) → (pA, pB, pC)`（精確機率，給出貨確認畫面公開）、`beef_expected_mult`、`draw_beef_grade(fp, cow, now, rng)`。
- **簽名改變**：`Farm.ship(cow, market, now, rng=None)`、`Farm.ship_many(cows, market, now, rng=None)`、`Farm.ship_to_storage(cow, now, rng=None)`。
  - **伺服器一定要傳 rng**（用 `game._rng(p, rng)`，和配種同一條亂數）。
  - 沒傳時用評級的期望倍率，`BeefLot.grade = −1`，不抽評級。只為了讓舊伺服器不壞，不是正式行為。
- **行為改變**：
  - 牛肉價格倍率從「肉質 × 稀有度」改成「評級倍率 × 稀有度」。`beef_quality()` 還在，但只當評級機率裡的年齡因素，不再直接乘在價格上。
  - `BeefLot.mult` = 評級倍率 × 稀有度倍率；`BeefLot` 多一個 `grade`（0 A、1 B、2 C；`to_dict` 第 6 個元素）。
  - 出貨前檢查 `Farm.can_ship(cow, now)`：成年、不在田裡、沒有上架。不符合時回傳 None。
- `beef_value_at_base` 改用評級期望值。
- 伺服器 `game.py:369` 的 `ship_value()` 還在用 `beef_quality × tier_mult` 估價，要改成 `beef_expected_mult(fp, cow, now)`。

### 2.4 商店

- 新增：`Farm.buy_shop(grade, now, rng)`，grade 是 "A"／"B"／"C" 或 0／1／2。用途、公母、稀有特徵都隨機，扣 `shop_grade_price`。
- 新增精確機率（給商店按鈕公開）：
  - `shop_grade_distribution(fp, grade) → {(用途, 是否公牛, 稀有特徵位元): 機率}`。
  - `shop_grade_tier_probs(fp, grade)`、`shop_grade_index`、`shop_grade_price`。
  - `shop_draw(fp, grade, rng)`。
- **行為改變**：
  - `buy_calf(type_idx, bull, now, rng)` 還能用（v0.1 選用途與公母，C 級基因，900 幣），但 v0.2 規則不允許選用途，伺服器要改成 `buy_shop`。
  - `shop_genotype(fp, type_idx, rng, q=None)` 的預設 q 從 0.15 改成 C 級的 0.1，所以開局的兩頭牛基因分布也跟著變。
- 伺服器 `views.py:177` 的 `"shop": {"calf_price": {...}}` 要改成三個等級的價格與機率。

### 2.5 配種

- **行為改變**：
  - `Farm.can_breed(sire, dam, now)` 改看兩頭都成年、`bred` 都是 False、都不在田裡或上架中、牛舍有空格；不再看冷卻。
  - `Farm.breed(...)` 會把公母的 `bred` 都設成 True。
  - 自己配種免費：`Farm.breed_cost()` 永遠回傳 0，`breed_fee(fp, sire, dam)` 也永遠回傳 0（名字保留）。
- 伺服器 `game.py:284–296` 的 `_breed_pair` 目前用 `now < c.ready_at` 判斷冷卻，要改成：
  - `c.bred` → 新的錯誤碼，例如 `already_bred`。
  - `c.field >= 0` → 例如 `cow_in_field`。
  - `c.listed is not None` → 例如 `cow_listed`。
- `breed_preview` 的 `normal_fee`、`first_free` 沒有意義了（都是 0／True），建議拿掉。

### 2.6 耕田（`Farm` 新方法）

| 方法 | 作用 |
|---|---|
| `next_field_cost()`、`expand_field(now)` | 開新田（第 2 塊 1,500 幣，之後每塊 ×1.6，最多 12 塊） |
| `can_work(cow, now)`、`assign_field(cow, idx, now)` | 成年耕牛（公母都行）、沒上架、不在別塊田，派到空田 |
| `recall(cow, now)` | 叫回來；田裡已長好的稻米留在田裡 |
| `free_field()` | 第一塊空田的編號（−1 = 沒有） |
| `field_preview(now)` | 不改狀態，算每塊田現在長了多少（畫面用） |
| `harvest(now)` | 所有田的稻米收進倉庫（一批 `RiceLot`），回傳公斤數 |
| `rice_rate(now)`、`rice_stock()`、`rice_lot_mult(lot, now)` | 查詢 |
| `quote_rice(market, qty, now)`、`sell_rice(market, qty, now)`、`sell_all_rice(market, now)` | 和牛肉一樣，最舊的先賣 |

- `Farm.advance(now)` 現在同時結算奶桶和田地。
- `Farm.to_dict()` 多 `fields`、`rice_lots`；`impact` 多 `rice`。
- `Farm.net_worth(now, milk_price, beef_price, rice_price=None)` 多一個參數，沒給就用稻米基本價。
- 設計差異（研究筆記 9.2 有說明）：企劃書寫「耕地 → 種稻 → 一段時間後收成」，引擎用的是「稻米持續長在田裡，最多存 8 小時的量，收成時進倉庫」，算法和奶桶相同。畫面可以把「田裡的量 ÷ 上限」畫成稻子的生長階段。要改成分段週期，只要改 `_advance_fields`。

### 2.7 借種市場 `StudMarket`（新）

全服一份，存檔 `to_dict()／from_dict(params, d)`（純 JSON）。

| 方法 | 作用 |
|---|---|
| `list_bull(farm, owner, cow, price, now)` | 主人上架：成年、沒配過、沒在田裡的公牛；price 要是 `stud_prices` 其中一檔。成功時 `cow.listed = 上架編號` |
| `unlist(lid, farm=None)` | 下架（給主人的牧場，會清掉公牛的上架標記） |
| `cheapest(ctype, tier, exclude_owner=None)` | 某用途、某稀有度最便宜的一筆（有索引，不用掃全部） |
| `owner_listings(owner)`、`listings` | 查詢 |
| `can_borrow(...)`、`borrow(lid, borrower_farm, borrower_id, dam, now, rng, owner_farm=None)` | 借種：付錢給主人（電腦假玩家上架的錢不給任何人）；小牛放在借的人牧場；公母的 `bred` 都設成 True；上架移除。失敗回傳 None、狀態不變 |
| `npc_refill(now, rng)` | 電腦假玩家維持至少 3 筆上架（一般公牛、300 幣，用途輪流） |

伺服器要做的事：
- 新增一張上架表（或把 `StudMarket.to_dict()` 存成一列 JSONB）。
- `borrow` 要在同一個交易裡鎖住借的人牧場、主人牧場（電腦假玩家沒有）和上架清單三列，照 T1「先檢查、後修改」。
- 主人出貨、上架中的公牛會被 `can_ship` 擋掉，要先 `unlist`。
- 公牛死掉（被出貨）以後的上架要清掉，`can_borrow` 也會檢查。
- 精確機率：借種前用 `offspring_distribution(listing.g, dam.g)` 公開，和自己配種相同。
- 模擬的成交紀錄在 `sim/world.py` 的 `stud_log`；伺服器可以記成交紀錄表，排行榜可以加「出借收入」。

### 2.8 行情（`cowecon/market.py`）

- `Exchange(params, seed, t0, commodity_ids=None, ...)`：沒給商品清單就用 `params.commodity_ids`（三種）。v0.1 預設是兩種。
- `EventGenerator` 的預設商品是三種，抽對象改用 `params.events.targets`。
- `Market`、`ImpactState`、存檔格式都沒變。

### 2.9 匯出（`cowecon/__init__.py`）

新增：`COMMODITY_IDS`、`Field`、`RiceLot`、`StudListing`、`StudMarket`、`beef_grade_probs`、`shop_grade_distribution`、`shop_grade_tier_probs`。v0.1 的名字都還在。

### 2.10 外觀規則（D18）

「肉牛＋C 光澤有短角」只影響外觀。引擎沒有角的欄位，也不需要：畫面用 `cow_type(g) == 2` 且 `rare_mask(g) & 0b100`（C 顯現）判斷就好。

## 4. 會壞的伺服器測試（v0.2 第一版、伺服器還沒改之前的紀錄；v0.2.1 的最新結果見開頭）

實測方式：
- 2026-09-30 在這台電腦用 `backend/.venv` 跑 `pytest -p no:cacheprovider -q`，並設 `PYTHONDONTWRITEBYTECODE=1`，用 `systemd-run` 限 1,500 MB，不寫任何檔案進 `backend/`。
- 當時 PostgreSQL 有開，所以資料庫測試也有跑；測試會自己建立、刪除 `cowfarm_test_` 開頭的資料庫。

**結果：13 個通過、1 個跳過、9 個失敗、15 個錯誤。**

### 4.1 伺服器一啟動就壞（`KeyError: 'rice'`）

- 原因：`server/runtime.py:248` 的 `self.history[cid].append(...)`。`history` 只為 milk、beef 建了清單，但 `Exchange` 現在有三個市場。
- 修法：`history` 改成照 `ex.markets` 建。第 473、504 行的 `for cid in ("milk", "beef")` 也一起改掉（見 1.1）。
- 受影響（19 個）：
  - `test_api.py` 全部 16 個：15 個在 fixture 出錯（ERROR），`test_static_web_dir` 失敗（FAILED）。
  - `test_recovery.py` 3 個：`test_restore_is_exact`、`test_resume_after_crash_equals_uninterrupted`、`test_real_server_survives_sigkill`。

### 4.2 經濟情境和研究模擬的比對（5 個）
